# KNOBI-SIX plugin (AU / VST3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** KNOBI-SIX as an AU / VST3 instrument for Ableton Live 12 on João's Mac — the firmware's own synth, arp, clock and sequencer inside a JUCE plugin with a full OB-6-style panel, Live automation, a shared 500-program bank and a mouse-editable sequencer.

**Architecture:** The firmware's behaviour code (synth/, engine.c, params/, the sequencer, arp, clock, ui/midi_map.c, ui/seq_rec.c) is built a second time as a host library `knobi_core` with a small C API and per-instance state; the firmware build keeps compiling the same files. A JUCE plugin (`plugin/`, CMake) drives one core instance per plugin instance on the audio thread: 44.1 kHz internal rendering in the firmware's block model, a FIFO and resampler to the session rate, MIDI and automation applied at sample offsets, Live's transport fed to a new clock entry point. A library file holds the user layer of the bank; the factory layer is compiled in only on an explicit local option.

**Tech Stack:** C (firmware modules, unchanged chip rules for the device build), C++17 + JUCE 8 (pinned via CMake FetchContent), CMake + Xcode 26.6 on macOS (Apple Silicon), `auval`, host unit tests (`make -C tests unit`), plugin unit tests (CTest), GitHub Actions (existing firmware jobs + a new macOS plugin job).

**Spec:** `docs/superpowers/specs/2026-11-19-plugin-design.md` (binding, incl. "Design decided with João" and both "Our calls" sections); firmware behaviour per the firmware specs and `docs/ob6-reference.md`.

## Global Constraints

- One source of truth: the plugin compiles the firmware's files; no copied DSP. Any refactor of firmware files keeps the device build's behaviour identical: all firmware unit tests, host scripts, wav checks, fm1-emu and cpu1-emu checksums unchanged, the loader byte-identical, the default image differing only where a refactor moves code (reported).
- CPU1 path compiled out in the plugin (`KNOBI_CPU1=0`); never any install/flash path in the plugin; NEVER run tools/fm1_install.py, flash, USB rescue or tools/backup/.
- Multiple plugin instances in one Live set must run concurrently on different threads with fully separate state (no shared mutable globals across instances).
- Audio thread real-time safe: no allocation, locks, file I/O or logging in processBlock.
- Internal render at 44.1 kHz in the firmware's block model; resampled to the session rate; latency reported to the host. Bit-exact with the firmware host build (tests/host.c) at 44.1 kHz before resampling, for the same event split.
- Parameters: every live id as a JUCE parameter with its firmware id as a stable parameter ID; switches → bool, selects → choice, knobs → integer steps (bipolar centred); not exposed: stored-only FX ids, P_SEQ_GEN, chord, name. Program loads update values without writing automation.
- Library: `~/Music/KNOBI-SIX/library.knobi` — header + 500 user slots (empty = factory, else full program + sequence in firmware packed records) + globals; atomic temp + rename; last write wins; instances reload on file change.
- Factory bank: CMake option `KNOBI_FACTORY_LOCAL` OFF by default; ON compiles `firmware/gen/factory_bank.h` and names the bundles `KNOBI-SIX-local`; CI never sets it; no OB-6 data or names committed.
- Sequencer edits (step entry and mouse) stay within the firmware's limits and rules (64 steps, 6 notes, 12–108, tie rules), through the edit-buffer path.
- JUCE under GPL (project is GPL-3.0); credits added to LICENSING.md and README, never dropped.
- Branch `plugin` from `phase1`; push only that branch.

## Review Focus

1. **Two instances at once** — two plugin instances rendering on two threads give exactly the output each gives alone. Test: Task 2 `two_instances_parallel` (TSan).
2. **Real-time safety** — processBlock never allocates or locks, including program loads, parameter storms and bank reloads. Test: Task 3 `rt_no_alloc` (allocation hook in tests) and Task 6 `reload_off_audio_thread`.
3. **Live transport edge cases** — start mid-bar, loop wrap, locate while playing, tempo automation, stop → internal clock: the arp/sequencer step matches Live's position. Test: Task 5 `transport_*`.
4. **Saved sets survive** — set state round-trip incl. edited program + sequence, bank changed since, plugin updated (parameter IDs stable). Test: Task 4 `state_roundtrip`, `state_bank_changed`.
5. **Library file under concurrency** — two instances WRITE near-simultaneously; a crash mid-write; a corrupt file: never a lost or half-written bank, every instance ends consistent. Test: Task 6 `library_atomic`, `library_two_writers`, `library_corrupt`.
