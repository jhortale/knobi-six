# KNOBI-SIX — Phase 2 (dual core first; clock, arp, distortion) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the AC791N's second core usable for the voices (off by default, safe fallback, a device probe build), and add the clock, arpeggiator and distortion — leaving effects for a later plan once real dual-core numbers exist.

**Architecture:** A render seam lets any subset of voices render into its own int32 bus (bit-exact sums). The CPU1 HAL comes from felucca-bsp (MPL-2.0) behind `KNOBI_CPU1`; inside the audio interrupt, core 0 forks half the voices to core 1 per 16-frame control period and joins before mixing (no added latency). Clock/arp/distortion are ordinary synth features on the reserved phase-2 param ids.

**Tech Stack:** C (JieLi pi32v2 clang, `-Os`, `-mfprev1`), host unit tests (`make -C tests unit`) + ThreadSanitizer, host scripts (`tests/run_host.sh`), fm1-emu dual-core mode (pinned `60645a5`, `run_dual`, `--flaky-core1`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-17-phase2-design.md` (extends `2026-11-16-standalone-firmware-design.md`), research `docs/research/second-core.md` (§3 is binding where marked [F]), reference `docs/ob6-reference.md` §4–§5.

## Global Constraints

- Everything from the Phase 1 plan's Global Constraints still holds (chip rules, ISR rules, identity, no OB-6 data, never install without João).
- Dual core: build flag `KNOBI_CPU1` (default 0 in CI and release) **and** global option DUAL CORE (default OFF). With either off, behaviour and output are identical to Phase 1.
- No pipelined render; fork/join inside the block only. Join timeout < 1 block; on timeout or CPU1 fault → CPU1 retired, single core for the session, Globals shows `C1 FAIL`.
- CPU1 held on every reset / loader / update / rescue path; never started in `recovery_main`; a CPU1 start failure must not count against the boot guard.
- Every flash erase/write waits for CPU1 idle in RAM.
- No supply-voltage (SYSVDD/VDC14/DCDC) changes in this plan.
- felucca-bsp files keep their MPL-2.0 headers; credit in LICENSING.md.
- Branch `phase2` from `phase1` HEAD; push to origin only that branch.

## Review Focus

1. **Bit-exactness** of split rendering (any voice partition, any block) vs single core — test `split_render_bitexact` (Task 1) and in fm1-emu (Task 3).
2. **CPU1 hang / fault / no-start** never breaks audio for more than one block and never bricks/rescues — fm1-emu cases `nostart`, `hang`, `--flaky-core1` (Tasks 2–3).
3. **Flash save with CPU1 on** (WRITE, autosave, sliced) — CPU1 idle in RAM, no fault — emu script `write_dual` (Task 3).
4. **Arp + HOLD relatch / append** and arp with external clock stopped — host scripts (Task 6).
5. **Distortion + limiter + DC blocker** at max drive: no wrap, no DC — test (Task 7).
