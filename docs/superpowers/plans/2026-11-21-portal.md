# midi-chlorian Portal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The public midi-chlorian portal: a static site (home + one page per synth with install, downloads and
releases) built from published Sanity content, with CI drafting releases into Sanity and a publish-triggered deploy
to GitHub Pages.

**Architecture:** The installer's behaviour and view move into `@knobi/installer-ui` so the portal and the dev
installer share them. `@knobi/content` holds the Sanity model (types, Studio schema), the GROQ queries, the release
draft writer and the site builder (Node). `apps/portal` renders `content.json` + `catalog.json`; `apps/studio` is the
Sanity Studio. `release.yml` drafts, `portal.yml` deploys.

**Tech Stack:** pnpm 12.21.0 + Turborepo 2.11.13, Node 24, Vite 8.3.8, React 19.3.1, TypeScript 7.0.2, Tailwind
4.3.5 + shadcn (`@knobi/ui`), `@knobi/field` (three.js), Sanity Studio `sanity` 6.24.0, `@sanity/client` 8.17.0,
Vitest 5.1.1, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-20-portal-design.md` (approved 2026-11-21; binding, including its "Rules
settled after review").

## Global Constraints

- CLAUDE.md: never install on a real keyboard; the installer runs only against `@knobi/device-sim` (`?mock`, tests).
  Upstream's paths (`firmware/`, `tools/`, `tests/`, `build.sh`) are not touched.
- Monorepo rules (`docs/MONOREPO.md`): packages `private`, scope `@knobi/`, exact pins (`saveExact`), one lockfile
  that installs on Linux and macOS (check in a `node:24` container before the PR), no cycles, `@knobi/device-sim`
  only as a devDependency and never in a published build.
- Names: site **midi-chlorian**, `https://jhortale.github.io/midi-chlorian/`, deploy repo `jhortale/midi-chlorian`
  (branch `gh-pages`), secrets `SANITY_WRITE_TOKEN`, `SANITY_READ_TOKEN`, `MIDI_CHLORIAN_DEPLOY_KEY`; dispatch event
  type `sanity-publish`; Sanity project id and dataset from env `SANITY_PROJECT_ID`, `SANITY_DATASET` (default
  `production`), API version `2026-11-01`.
- Release tags: `<synth>-v<version>`, e.g. `knobi-six-v1.0`; no `-` after `v<version>` (no prereleases).
- Document ids: synth `synth.<id>`, release `release.<synth>.<version>`; drafts `drafts.` + id. CI never publishes.
- A published release never changes; CI-owned release fields: `synth`, `version`, `date`, `tag`, `source`, `builds`;
  João-owned: `notes`, `current`. Repo-owned synth data (never from Sanity): `id`, `license`, identities and package
  names (`synth.json`), the install warning (`synths/<id>/catalog.json` `notes`). Sanity-owned: name, summary,
  description, image, order.
- Provenance: every file on the site comes from a GitHub release of `jhortale/knobi-six` whose asset uploader is
  `github-actions[bot]`, and matches the release's `SHA256SUMS` and Sanity's SHA-256; keyboard packages pass
  `loadPackage` (identity, loader mark). Never a `-local` or `cpu1` file.
- No token in the repo or the site: tokens only in GitHub secrets / Sanity's webhook settings.
- GPL-3.0-only for new code; `LICENSING.md` gains rows (Sanity Studio, `@sanity/client`: MIT); never drop one.
- Commits: conventional, ending with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A Sanity release edited by hand** (hashes, files changed despite read-only fields, or a file missing from the
   GitHub release): the deploy stops with an error naming the release and the file; nothing deploys. Test in Task 4.
2. **More than one `current` release for a synth, or none**: more than one → the deploy stops naming both; none → the
   newest published version is current. Test in Task 4.
3. **A Sanity synth without `synths/<id>/`, or a repo synth not in Sanity**: the first stops the deploy naming it; the
   second is simply not listed. Test in Task 4.
4. **A token reaching `dist/`** (the read token's value, or `sk…`/`ghp_`/`github_pat_`-shaped strings): the deploy
   refuses. Test in Task 4.
5. **Deep links on GitHub Pages**: `/midi-chlorian/knobi-six/` opened directly or reloaded works; an unknown path shows
   a 404 page linking home. Test in Task 5.
