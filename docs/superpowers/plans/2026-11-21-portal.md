# midi-chlorian Portal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The public midi-chlorian portal: a static site (home + one page per synth with install, downloads and
releases) built from Markdown content in the repo, with CI opening a release pull request on each tag and a
merge-triggered deploy to GitHub Pages.

> **Amended 2026-11-21:** João switched the content from Sanity to Markdown with frontmatter (spec amendment at the
> end of the design). Task 1 was done before; Tasks 2-6 below replace the Sanity tasks (the Studio task is gone).

**Architecture:** The installer's behaviour and view move into `@knobi/installer-ui` so the portal and the dev
installer share them. `@knobi/content` holds the content model (types), the Markdown/frontmatter reader and validator,
the release-file writer and the site builder (Node). `apps/portal` renders `content.json` + `catalog.json`.
`release.yml` opens the release PR, `portal.yml` deploys.

**Tech Stack:** pnpm 12.21.0 + Turborepo 2.11.13, Node 24, Vite 8.3.8, React 19.3.1, TypeScript 7.0.2, Tailwind
4.3.5 + shadcn (`@knobi/ui`), `@knobi/field` (three.js), Sanity Studio `sanity` 6.24.0, `@sanity/client` 8.17.0,
Vitest 5.1.1, `yaml` 2.9.1, `marked` 18.2.1, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-20-portal-design.md` (approved 2026-11-21; binding, including its "Rules
settled after review").

## Global Constraints

- CLAUDE.md: never install on a real keyboard; the installer runs only against `@knobi/device-sim` (`?mock`, tests).
  Upstream's paths (`firmware/`, `tools/`, `tests/`, `build.sh`) are not touched.
- Monorepo rules (`docs/MONOREPO.md`): packages `private`, scope `@knobi/`, exact pins (`saveExact`), one lockfile
  that installs on Linux and macOS (check in a `node:24` container before the PR), no cycles, `@knobi/device-sim`
  only as a devDependency and never in a published build.
- Names: site **midi-chlorian**, `https://jhortale.github.io/midi-chlorian/`, deploy repo `jhortale/midi-chlorian`
  (branch `gh-pages`), secret `MIDI_CHLORIAN_DEPLOY_KEY`.
- Release tags: `<synth>-v<version>`, e.g. `knobi-six-v1.0`; no `-` after `v<version>` (no prereleases).
- Content: `synths/<id>/synth.md` (frontmatter `name`, `summary`, `order`, `image?`, `origin`; body = description)
  and `synths/<id>/releases/<version>.md` (frontmatter `version`, `date`, `tag`, `current?`, `source`, `builds`; body
  = notes). Published = merged into `main`; a release PR is the draft. CI never merges.
- A published release never changes; CI-owned release fields: `version`, `date`, `tag`, `source`, `builds`;
  João-owned: the body (notes) and `current`. Repo-owned synth data stays in `synth.json` / `catalog.json` (`id`,
  `license`, identities, package names, the install warning); `synth.md` holds the display text.
- Provenance: every file on the site comes from a GitHub release of `jhortale/knobi-six` whose asset uploader is
  `github-actions[bot]`, and matches the release's `SHA256SUMS` and the release file's SHA-256; keyboard packages pass
  `loadPackage` (identity, loader mark). Never a `-local` or `cpu1` file.
- Markdown rendered at build time with `marked`, raw HTML escaped. No token in the repo or the site.
- GPL-3.0-only for new code; `LICENSING.md` gains rows (`yaml`: ISC, `marked`: MIT); never drop one.
- Commits: conventional, ending with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A release file edited by hand** (hashes or files changed after merge, or a file missing from the GitHub
   release): the deploy stops with an error naming the release and the file; nothing deploys. Test in Task 4.
2. **More than one `current` release for a synth, or none**: more than one → the deploy stops naming both; none → the
   newest published version is current. Test in Task 4.
3. **A synth folder with `synth.json` but no `synth.md`, or a broken frontmatter**: the first is not listed; the second
   stops the build naming the file and field. Test in Task 2.
4. **Raw HTML or a script tag in a release note**: it is shown as text, never executed. Test in Task 2.
5. **Deep links on GitHub Pages**: `/midi-chlorian/knobi-six/` opened directly or reloaded works; an unknown path shows
   a 404 page linking home. Test in Task 5.
